# Studio AKASAKA - Webアップロードルール

## 目的

以下の依頼を受けた場合、このルールに従って作業してください。

-   web-akasaka フォルダをアップロード
-   Webサイトを公開
-   Webサイトを更新
-   本番サイトへデプロイ

------------------------------------------------------------------------

## 作業手順

### 1. 最初に比較する

アップロードを開始する前に必ず以下を行うこと。

-   ローカルの `web-akasaka`
    フォルダと現在公開されているWebサイトを比較する。
-   変更点をまとめる。
-   追加・変更・削除されたファイルを一覧にする。

この手順は省略しない。

### 2. ユーザーの承認を待つ

比較結果を報告した後、必ずユーザーの承認を待つ。

以下のような明確な指示があるまでアップロードしない。

-   アップロード
-   デプロイ
-   公開
-   OK
-   進めて

承認がない場合は作業を終了する。

### 3. アップロード

承認後のみ実行する。

-   今回必要なファイルだけをアップロードする。
-   関係のないファイルは変更しない。
-   プロジェクト構成を変更しない。
-   依存関係を追加・更新しない。

### 4. 確認

アップロード後は必ず確認する。

-   デプロイが正常終了したこと
-   Webサイトへアクセスできること
-   エラーや警告がないこと

## 安全ルール

以下は禁止する。

-   ユーザー確認なしで既存ファイルを上書きすること
-   指示なしでファイルを削除すること
-   package.json を変更すること
-   ライブラリ・依存関係を更新すること
-   ビルド設定を変更すること
-   デザインやレイアウトを変更すること

## ブランド保護

公開中のWebサイトは本番環境として扱う。

今回の更新とは無関係なページやコンテンツへ影響する可能性がある場合は、作業前に必ず警告する。

## 最小変更原則

目的を達成するために必要最小限の変更のみ行う。

今回の依頼と関係のない改善、整理、リファクタリング、コード整形、デザイン変更を行う場合は、事前に内容と影響範囲を説明し、ユーザーの承認を得る。

## 作業報告

作業終了後は必ず報告する。

-   変更したファイル
-   アップロードしたファイル
-   デプロイ結果
-   エラー・警告の有無
-   気になる点や注意点

## 不明な場合

推測で作業しない。

判断できない場合は必ずユーザーへ質問してから作業を続ける。
